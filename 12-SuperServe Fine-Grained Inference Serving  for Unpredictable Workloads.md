# SuperServe: Fine-Grained Inference Serving  for Unpredictable Workloads

Date: 2026-09-25

- [Link](https://www.usenix.org/conference/nsdi25/presentation/khare)

- Problem: Existing serving systems struggle to handle unpredictable and bursty request arrival rates while balancing latency, accuracy, and GPU memory use. A fixed model may miss latency targets during bursts or sacrifice accuracy under light load, while switching models incurs model-loading latency and keeping multiple models loaded consumes GPU memory.
- Solution: The authors propose SuperServe, which combines SubNetAct, a mechanism that uses control-flow operators to activate weight-shared SubNets in place, and SlackFit, a greedy scheduling policy that selects a SubNet and batch size based on request slack.
- Claimed technical contributions:
  - Model loading can take longer than inference, making it costly to switch model variants as request rates change. A SubNet uses a subset of a trained SuperNet’s blocks and weights, so multiple SubNets can share those weights without separate training. Prior works typically extract and deploy these SubNets separately. SubNetAct instead keeps one SuperNet on the GPU and activates SubNets in place using LayerSelect, which selects blocks according to the depth setting for each stage, and WeightSlice, which selects a fraction of convolution channels or attention heads. For convolutional SubNets, SubnetNorm stores separately calibrated BatchNorm statistics because changing the architecture changes activation distributions. The system then searches for Pareto-optimal SubNets and profiles their accuracy and latency at different batch sizes for scheduling.
  - The authors formulate an idealized offline scheduling policy as a zero-one integer linear program (ZILP). It assumes knowledge of future requests and chooses the SubNet, batch, GPU, and start time to maximize the accuracy of responses completed within their deadlines. It cannot be used online because future arrivals are unknown and solving it is computationally expensive. The authors therefore introduce SlackFit, a greedy policy designed to approximate its behavior. Offline, SlackFit groups profiled SubNet and batch-size choices into evenly sized latency buckets, favoring a larger batch within each bucket. Online, it chooses the bucket whose batch latency is closest to but less than the remaining slack of the earliest-deadline request, then batches the earliest-deadline queries.
- Metrics / Baselines:
  - The authors evaluate ImageNet-trained ResNet and MNLI-trained transformer SuperNets on eight RTX 2080 Ti GPUs, using a compressed Microsoft Azure Functions (MAF) arrival trace and synthetic traces. The main metrics are SLO attainment (the fraction of requests completed by their deadline) and mean serving accuracy (the average profiled SubNet accuracy for on-time requests). They also measure GPU memory, SubNet actuation latency, and throughput.
  - Clipper+ serves one of six fixed SubNets in each configuration. INFaaS is run without query accuracy thresholds, so it selects the least-cost, lowest-accuracy model. The policy comparison also includes MaxAcc and MaxBatch.
  - On the transformed MAF trace, SuperServe reaches 0.99999 SLO attainment for CNNs. Figure 8 reports about 4.7 percentage points higher mean serving accuracy at matched SLO attainment, or 2.85× higher attainment at matched accuracy. The corresponding transformer results are 1.72 percentage points and 1.2×.
  - In the SubNetAct microbenchmark, 500 in-place SubNets use about 200 MB, versus 531 MB for six separately extracted SubNets; measured SubNet actuation takes under 1 ms (Figure 5).
- Key insight and enabling idea: A trained, weight-shared SuperNet contains many SubNets, so the system can change its accuracy–latency choice without loading a separate model. SubNetAct activates the chosen SubNet in place, allowing SlackFit to react to request slack by changing the SubNet and batch size as traffic varies.
- Novelty and impact: SuperServe enables SubNets to be activated within one deployed SuperNet instead of extracting them as separate models, including separate normalization statistics where needed. This enables fine-grained scheduling of both SubNet and batch size; in the tested workloads, it reduces GPU memory use and improves the accuracy–SLO attainment tradeoff over the evaluated baselines.
- Technical Qualities: 
  - Framing and assumptions: The approach assumes an already trained SuperNet with useful accuracy–latency choices, reliable SubNet profiles, and enough GPU memory to keep the full SuperNet resident. It permits lower model accuracy during bursts to protect request deadlines.
  - Merits of the technical contributions: SubNetAct avoids loading separate model variants and shares their weights; SubnetNorm preserves the appropriate BatchNorm statistics. SlackFit uses request slack to jointly choose a SubNet and batch size without predicting future arrivals.
  - Does the evaluation support claims and reveal limitations of the proposed approach?: The mechanism benchmarks support the reported memory and actuation benefits, while real-trace-derived and synthetic workloads show improved accuracy–SLO tradeoffs in the tested settings. The worker-failure experiment shows adaptation as workers are removed, but the evaluation does not establish router fault tolerance or performance on an actual ML inference trace.
- Criticism:
  - SuperServe keeps the full SuperNet in GPU memory even when an application needs only one small, low-accuracy model. The memory comparison is against sets of separate models, so it does not show when this flexibility is worth the memory cost relative to serving one small model.
  - SlackFit has no explicit minimum-accuracy constraint for a request and may choose a lower-accuracy SubNet during bursts. Its reported serving accuracy averages profiled model accuracies for on-time requests, rather than measuring correctness on the trace’s requests.
  - Figure 11 tests worker failures, but not failure or recovery of the central router and its global earliest-deadline-first queue. Router fault tolerance therefore remains untested.
  - The INFaaS baseline is run without accuracy thresholds, so its cost-minimizing policy appropriately selects the lowest-cost variant. The resulting accuracy comparison shows SuperServe’s benefit when applications provide deadlines but no minimum accuracy requirement; it does not cover INFaaS’s intended accuracy-constrained use case.
  - The Microsoft Azure Functions trace provides per-minute function-invocation counts, which the authors transform from 24 hours into a 120-second arrival pattern. It is not a trace of these models serving real application inputs, which limits how directly the result transfers to deployment.
