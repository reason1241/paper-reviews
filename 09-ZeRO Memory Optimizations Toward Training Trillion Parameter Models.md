# ZeRO: Memory Optimizations Toward Training Trillion  Parameter Models

Date: 2026-09-16

- [Link](https://arxiv.org/abs/1910.02054)

- Problem: Training large models requires substantial memory for parameters, gradients, optimizer states, and activations. Standard data parallelism replicates model states across GPUs, limiting the model size each GPU can accommodate.
- Solution: They propose ZeRO, which partitions model states across data-parallel workers (ZeRO-DP) and reduces memory consumed by activations, temporary buffers, and fragmentation (ZeRO-R). Their implementation, ZeRO-100B, combines the first two partitioning stages with ZeRO-R and supports models up to 170B parameters when combined with model parallelism.
- Claimed technical contributions:
  - **ZeRO-DP** consists of three cumulative optimization stages: (1) optimizer-state partitioning distributes FP32 master parameters and Adam’s first and second moments across data-parallel workers, providing up to a 4× reduction in model-state memory with the same communication volume as standard DP; (2) gradient partitioning additionally distributes reduced gradients, increasing the memory reduction to up to 8× without increasing communication volume; (3) parameter partitioning additionally distributes working parameters and gathers them when needed, reducing model-state memory proportionally to the data-parallel group size with 1.5× the baseline communication volume.
  - **ZeRO-R** consists of three residual-memory optimizations: (1) partitioned activation checkpointing distributes saved activation checkpoints across model-parallel workers, reconstructing them when needed to recompute intermediate activations during backpropagation, with optional CPU offloading; (2) constant-size buffers bound temporary memory independently of model size while remaining large enough for efficient computation and communication; (3) memory defragmentation places long-lived activation checkpoints and parameter gradients into preallocated contiguous buffers as they are produced, reducing their interleaving with short-lived allocations and improving memory availability and allocation efficiency.
- Metrics / Baselines:
  - They evaluated GPT-2-like Transformer models on a cluster of up to 400 NVIDIA V100 GPUs across 25 DGX-2 nodes. They used PyTorch DDP as the baseline without model parallelism and the September 2019 version of Megatron-LM as the baseline with model parallelism.
  - They measured throughput per GPU and supported model size. ZeRO-100B combined with model parallelism runs models up to 170B parameters and achieves approximately 38 TFLOP/s per GPU for a 100B model, with up to approximately 10× higher throughput than the baseline. Memory savings allow larger local batches and keep model parallelism within a node, avoiding slower communication between nodes (Figure 2).
  - They demonstrated superlinear throughput scaling for a 60B model across 64–400 GPUs. Increasing the data-parallel group size reduces memory consumption per GPU, allowing larger local batches and improving GPU utilization (Figure 3).
  - Without model parallelism, ZeRO-100B supports models up to 13B parameters on 128 GPUs, compared with approximately 1.4B parameters for standard DDP (Figure 4).
  - They compared optimization configurations using maximum supported model size, peak cached GPU memory, and throughput. Activation partitioning and gradient partitioning improve capacity and performance, while CPU offloading enables larger models but can reduce throughput because of additional transfers (Figures 6–8).
  - They demonstrated end-to-end training of the 17B-parameter Turing-NLG model and compared its validation perplexity with an 8.3B Megatron-LM model. This demonstrates practical use, although the different model sizes prevent a controlled comparison of training-system effects on convergence (Figure 5).
- Key insight and enabling idea: Data-parallel workers do not need to retain identical copies of all training states, and not every state is needed throughout the entire training step. ZeRO assigns ownership of parameter updates, retains reduced gradients only on their owners, and gathers partitioned parameters when needed, reducing memory redundancy while keeping communication volume close to standard DP.
- Novelty and impact: The paper introduces a systematic approach to partitioning optimizer states, gradients, and parameters across data-parallel workers, combining these techniques with residual-memory optimizations. This substantially increases supported model sizes and throughput while preserving the familiar data-parallel interface and reducing the need for model-specific parallelization.
- Technical Qualities:
  - Framing and assumptions: The paper clearly separates model-state memory from activation, temporary-buffer, and fragmentation overheads. Its numerical memory reductions assume mixed-precision Adam, while its communication analysis focuses on data volume under bandwidth-dominated conditions rather than fully modeling latency, overlap, or peak working memory.
  - Merits of the technical contributions: The staged design provides explicit memory–communication trade-offs while preserving the intended optimizer update rule. Combining state partitioning with activation checkpoint partitioning, bounded buffers, and defragmentation addresses multiple memory bottlenecks and translates memory savings into larger batches and higher throughput.
  - Does the evaluation support claims and reveal limitations of the proposed approach?: The experiments support the capacity and throughput benefits of ZeRO-100B and reveal the transfer costs of CPU offloading. However, the evaluated implementation includes only the first two ZeRO-DP stages plus ZeRO-R; Stage 3 and trillion-parameter capacity remain analytical claims in this version. Changing batch sizes and parallelism configurations also means the throughput gains do not establish equivalent improvements in time to a target model quality.
- Criticism: The evaluated implementation does not include ZeRO-DP Stage 3, so its memory and communication benefits remain analytically supported rather than experimentally validated. Trillion-parameter capacity is also projected rather than demonstrated through actual training. Although the paper includes optimization ablations, batch sizes and parallelism configurations vary across performance comparisons, making it difficult to isolate each optimization’s direct contribution to throughput.
